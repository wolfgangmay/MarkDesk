[^note2]: 另一个简短脚注。

## 九、推过分页的长尾内容

以下连续段落把文档推过多个页面边界,用于综合观察:标题跟随性(不孤悬页底)、孤行/寡行控制、段落间无异常空隙。

段落一:软件工程是一门研究如何系统化、规范化、可量化地开发和维护软件的学科。它涵盖需求分析、设计、实现、测试、部署与运维等全生命周期活动。

段落二:版本控制是软件工程的基础实践。集中式版本控制(SVN)与分布式版本控制(Git)各有优劣;当前主流是 Git 工作流,包括 feature 分支、pull request 评审与持续集成。

段落三:持续集成(CI)要求每次提交都自动构建与测试;持续交付(CD)进一步要求随时可发布。GitHub Actions 是本仓库使用的 CI 平台。

段落四:代码评审提升代码质量与知识共享。评审关注正确性、可读性、性能、安全性与测试覆盖,而不是个人风格偏好。

段落五:文档与代码同等重要。高质量的 README、架构决策记录(ADR)与 API 文档能显著降低协作成本——本文档自身即是一个排版与文档质量的测试载体。

段落六:测试金字塔建议:大量快速单元测试为基础,适量的集成测试为中层,少量的端到端测试为顶层。本仓库当前有五十个单元测试,全部通过。

段落七:性能优化应基于测量而非直觉。常见的性能工具包括 Profiler、火焰图与基准测试;过早优化是万恶之源,但架构级的性能考量应当尽早。

段落八:安全性包括输入验证、权限控制、密钥管理、依赖审计等。本应用不处理敏感数据,但仍遵循最小权限与依赖最少化原则。

段落九:可访问性(A11y)关注残障用户的使用体验,包括键盘导航、屏幕阅读器兼容与色彩对比度;桌面应用的 WPF 自动化树即服务于这一目标。

段落十:国际化(i18n)与本地化(l10n)让软件适应不同语言与地区;本应用界面当前为英文,但内容渲染已全面支持 CJK——上一份测试文档专门验证了这一点。
